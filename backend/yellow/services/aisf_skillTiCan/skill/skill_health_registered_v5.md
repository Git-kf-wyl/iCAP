## 适用场景
当用户表达以下意图时激活本 skill：
- 想要挂号、预约挂号、挂门诊
- 指定医院/科室/医生的挂号请求
- 挂普通号或专家号

## 参数提取规则
| 字段名 | 类型 | 必填 | 描述                        |
|--------|------|------|---------------------------|
| hospital | string | 否 | 挂号医院名称                    |
| department | string | 否 | 挂号科室名称                    |
| doctor | string | 否 | 挂号医生姓名                    |
| type | string | 否 | 号别：1=普通号，2=专家号            |
| startTime | string | 否 | 挂号开始时间，格式 YYYY-MM-DD hh:mm |
| endTime | string | 否 | 挂号结束时间，格式 YYYY-MM-DD hh:mm |

### 历史补全规则

当用户当前输入是泛化挂号请求，或当前字段在当前任务输入中未明确提供时，可以按以下规则从历史上下文或记忆信息中补全：

* hospital：优先使用最近一次成功挂号结果中的医院；如果没有最近一次成功挂号结果，再使用记忆信息中的常去医院。
* department：优先使用最近一次健康咨询、就诊建议或用户症状相关建议中明确推荐的科室；如果没有推荐科室，则不输出该字段。
* doctor：不自动沿用历史医生，除非用户明确承接，如“还是上次那个医生”“常看的医生”。
* startTime 和 endTime：不自动沿用历史时间，除非用户明确承接，如“还是上次那个时间”。
* type：不自动沿用历史号别，除非用户明确承接或当前输入明确出现“普通号”“专家号”。
* 如果同一字段存在多个候选且无法按上述优先级唯一确定，则不输出该字段。
* 如果历史助手回复中出现“建议尽快到XX门诊就诊”“建议XX科”“推荐XX科”“前往XX科室”，则 department 取 XX。

### 当前任务输入提取规则

* 如果当前 tool_call.function.arguments.content 中明确出现具体医院、科室、医生、时间或号别，应提取对应字段。
* content 中的具体医院、科室、医生可以和当前用户输入中的时间、号别等字段组合使用，只要它们能唯一对应到同一个挂号对象。
* 仅出现“医院、科室、医生、时间、号别”等字段名，或“需获取医院、科室、医生、时间、号别等信息”这类待补充说明，不算明确提供字段值，不得阻断历史补全规则。
* 多个挂号 tool_call 分别提参时，每个 tool_call 只使用自身 content 或能与自身唯一对应的当前用户输入片段，不得混入其他 tool_call 的信息。
* 当当前用户输入出现“第一个、第二个、第一条、第二条”等表达时，按用户表达顺序与同类 tool_call 顺序对应。
* 如果历史助手回复中出现“建议尽快到XX门诊就诊”“建议XX科”“推荐XX科”“前往XX科室”，则 `department` 取 XX。
* 如果当前 content 只是“需获取医院、科室、医生、时间、号别等信息”这类待补充说明，且历史中存在唯一明确推荐科室，必须输出 `department`。
* 如果存在多个候选科室且无法按最近一次健康咨询或就诊建议唯一确定，则不输出 `department`。


### 时间提取规则
- startTime 和 endTime 必须成对出现
- 模糊时间映射：
  - "早上/上午" → 07:00-12:00
  - "中午" → 11:00-13:00
  - "下午" → 12:00-18:00
  - "晚上" → 18:00-24:00
- 相对日期：
  - "今天" → 当天日期
  - "明天" → 当天日期 +1
  - "后天" → 当天日期 +2
- 如果用户未指定时间，不传 startTime 和 endTime

### 号别规则
- 用户说"普通号" → --type "1"
- 用户说"专家号" → --type "2"
- 未指定时不传

注意：挂号 type 只有在用户或当前任务输入明确出现“普通号”“专家号”时才输出。 仅出现“门诊”“挂号”“预约”“看看能不能约”等表达，不得推断 type。
