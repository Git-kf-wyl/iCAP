## 3. vite.config.js 逐段解析

```js
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
  server: { /* 见 3.2 */ },
  build: {
    rollupOptions: { output: { manualChunks: { /* 见 3.3 */ } } },
    chunkSizeWarningLimit: 1000,
    optimizeDeps: { include: ['vue','vue-router','vuex','element-plus','echarts'] },
  }
})
```

### 3.1 别名

| 别名 | 指向 | 说明 |
|---|---|---|
| `@` | `<root>/src` | 全工程唯一的路径别名 |

`jsconfig.json` 同步声明了 `"@/*": ["./src/*"]` 供 IDE 使用。

### 3.2 开发代理（4 条规则）

| 前缀 | 目标 | rewrite | 用途 |
|---|---|---|---|
| `/api` | `http://icap.rnd.huawei.com` | 去掉 `/api` | 通用后端代理 |
| `/api1` | `http://151.210.17.144:1050` | 去掉 `/api1` | 备用后端 1 |
| `/api2` | `http://151.210.17.144:1025` | 去掉 `/api2` | 备用后端 2 |
| `/api3` | `http://151.210.17.118:1025` | 去掉 `/api3` | 备用后端 3 |

全部 `changeOrigin: true`。

> ⚠️ **重要冲突**：`dataPipeline` 模块使用 `fetch('/api/...')` 且 `VITE_API_BASE_URL` 未设置时，
> 请求会命中 `/api` 代理规则并被 **rewrite 去掉 `/api` 前缀**，导致后端 404。
> 复现时需二选一：
> - 设置 `VITE_API_BASE_URL=/api-dp` 并新增对应代理规则；或
> - 修改 `/api` 的 rewrite 行为。
> 详见工程内既有的 `数据治理Pipeline_后端接口报告.md` 与 `API_BACKEND_MAPPING.md`。

### 3.3 构建分包（manualChunks）

| chunk 名 | 包含 |
|---|---|
| `vue-vendor` | vue, vue-router, vuex, pinia, vue-echarts |
| `element-ui` | element-plus |
| `element-icons` | @element-plus/icons-vue |
| `echarts-vendor` | echarts |
| `html2xx-vendor` | html2canvas, html2pdf.js, jspdf |
| `file-util-vendor` | file-saver, xlsx, markdown-it |
| `utils-vendor` | axios, js-audio-recorder, @wangeditor/editor-for-vue, jsencrypt |

- `chunkSizeWarningLimit: 1000`（kB）
- `optimizeDeps.include` 预打包 5 个核心库

> **注意**：`three`、`lodash`、`dayjs`、`exceljs`、`jszip`、`docxtemplater`、`pizzip`、
> `codemirror`、`marked` 等**未纳入 manualChunks**，会落到默认分包中。

## 5. 依赖缺口（重要）

以下模块在 `src/` 中**被 import**，但**未在 package.json 中声明**。
复现时必须补装，否则构建失败。

| 包 | 引用位置 | 安装方式 |
|---|---|---|
| `lodash` | `src/stores/datasetStore.js:3`、`src/components/modelSquare/modelSquare.vue:26` | `npm i lodash` |
| `dayjs` | `modelSquare.vue:25`、`src/components/statistics/evaluationStastics.vue:178` | `npm i dayjs` |
| `@vueuse/core` | `evaluationStastics.vue:182`（`import { useTransition }`） | `npm i @vueuse/core` |
| `vitest` | 19 个 `src/dataPipeline/**/*.test.ts` | `npm i -D vitest` |
| `vue-flow` / `@vue-flow/core` | **无 JS import**，但 `dataPipeline.global.css:102-112` 定义了 `.vue-flow__node`、`.vue-flow__node.selected` 样式 | 可选（仅样式兜底） |

**已验证**当前 `node_modules` 中：
- ✅ 存在：`lodash`、`dayjs`、`three`、`@vueuse/core`、`sass-embedded`、`docxtemplater`、`pizzip`、`codemirror`、`exceljs`、`jszip`、`highlight.js`、`marked`、`markdown-it`
- ❌ 缺失：`vitest`、`sortablejs`、`vue-flow`、`@vue-flow/core`
- `package-lock.json` 中虽含 `"@vueuse/core"`、`"dayjs"`、`"lodash"`、`"three"` 条目，
  但**不在 package.json 的依赖声明里** → 说明是传递依赖或历史残留，重新 `npm ci` 可能丢失。

> `sortablejs` 仅在 `dataSetSelectForm.vue:344` 的**注释**中出现，无需安装。

## 8. 从零复现的完整命令序列

```bash
# 1. 前置：Node 18+ / npm 9+
node -v && npm -v

# 2. 获取源码（含 src/、public/、配置文件）
#    ★ 必须包含二进制资源目录：src/assets、public/images、public/data、
#      src/dataPipeline/assets/overview-icons、public/llm_bench

# 3. 安装依赖
npm install

# 4. 补装 package.json 遗漏的依赖
npm i lodash dayjs @vueuse/core
npm i -D vitest

# 5. 启动
npm run dev        # → http://localhost:12096

# 6. 构建
npm run build      # → dist/
```
